## Trust Boundaries

| Boundary | Untrusted side | Trusted side | What is enforced at the crossing |
|---|---|---|---|
| OAuth redirect return | browser URL (hash/query with `code`/`token`/`state`) | plugin `initialize()` | CSRF `state.csrf_token` verification; error-param check; URL cleanup after read (`plugin-authorization-browser*/src/authorization.js`) |
| Authorization code exchange | authorization code from IdBroker | token endpoint call | PKCE `code_verifier` (first-party); client secret sent only server-side (node/confidential); 400 → typed grant error |
| Device (QR) polling | oauth-helper poll responses | first-party polling loop | `pollingId` guard ignores late/canceled responses; `slow_down`/`428` handled; overall timeout |

## Authentication & Authorization Model

- **Authentication:** OAuth 2.0 against Webex IdBroker. Flow selected by `clientType`: `'confidential'` → Authorization Code (`response_type=code`); anything else → Implicit (`response_type=token`) (`plugin-authorization-browser/src/authorization.js`, `src/config.js`). First-party uses Authorization Code + PKCE (S256).
- **Authorization:** delegated to Webex IdBroker scopes (e.g. `spark:all spark:kms`); these packages do not make local access decisions.
- **Default posture:** public client (implicit) unless explicitly configured confidential; the resulting `supertoken` is stored on `webex.credentials`.

## Secret & Credential Handling

- Secrets source: `client_secret` supplied via SDK config, used **only** by Node/confidential clients and first-party code exchange; never present in public browser implicit flow.
- Injection: passed as HTTP basic auth on the token request (`auth: {user: client_id, pass: client_secret}`).
- Rotation: `[NEEDS HUMAN INPUT]` — governed by the consumer's IdBroker app registration, not these packages.
- **Hard rule:** never commit secrets/tokens/keys; never log them. Tokens are set on `webex.credentials`, not logged.

## Data Classification & Handling

| Data class | Examples | Storage rule | Logging rule | In transit |
|---|---|---|---|---|
| OAuth tokens | access_token, refresh_token (supertoken) | held by `webex.credentials` / storage adapters | never logged | HTTPS to IdBroker |
| CSRF / PKCE artifacts | `oauth2-csrf-token`, `oauth2-code-verifier` | sessionStorage, single-use, removed after use | never logged | in state param (CSRF), never sent for verifier |
| PII | user email (first-party preauth) | hashed with SHA256 before propagation; raw email deleted from options | never logged raw | hashed only |

## Input Validation & Output Encoding Posture

- Redirect input is validated at the boundary: error params trigger a mapped `grantErrors` throw; `state` is base64-decoded and its CSRF token compared to the stored session token; `code` is required for code exchange. URL is rewritten via `history.replaceState` to strip `code`/tokens/`csrf_token`.

## Session & Cookie Posture

- CSRF token: UUID v4 generated by `_generateSecurityToken()`, stored in `sessionStorage` under `oauth2-csrf-token`, embedded in OAuth `state`, verified once and removed on return.
- PKCE verifier (first-party): 128-char base64url string in `sessionStorage` under `oauth2-code-verifier`, removed immediately when consumed during code exchange.
- No cookies are set by these packages; token lifetime/refresh is owned by the credentials plugin.
